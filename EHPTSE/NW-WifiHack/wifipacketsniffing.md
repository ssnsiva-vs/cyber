To do packet sniffing on Wi-Fi, you must capture raw data directly out of the air. Unlike wired networks, wireless traffic requires your network adapter to be placed in Monitor Mode (rather than Promiscuous Mode) so it can listen to all over-the-air packets on a specific radio channel, regardless of which device they are sent to. [1] 
Here is how to set up and perform Wi-Fi packet sniffing across different operating systems using [Wireshark](https://www.wireshark.org/download.html), the industry-standard network protocol analyzer. [2, 3] 
------------------------------
## Step 1: Identify Your Wi-Fi Channel
A wireless sniffer can generally only listen to one frequency channel at a time. You must find the channel your target devices are using: [1, 4] 

* On macOS: Hold Option and click the Wi-Fi icon in the top menu bar to view the current channel, width, and band.
* On Windows/Linux: Log into your router’s admin dashboard to see which fixed channel your Wi-Fi is broadcasting on.
* Tip: Configure your Wi-Fi router to a fixed channel rather than "Auto" so the channel doesn't shift mid-capture. [5, 6] 

------------------------------
## Step 2: Put Your Adapter into Monitor Mode## Option A: On macOS (Easiest)
Mac hardware natively supports monitor mode without extra software via the built-in Wireless Diagnostics tool. [5, 7] 

   1. Press Cmd + Space, search for Wireless Diagnostics, and open it.
   2. Ignore the setup wizard. Click Window in the top menu bar and select Sniffer.
   3. Choose the target Channel and Channel Width (e.g., 20MHz, 40MHz, 80MHz).
   4. Click Start. The Mac will disconnect from its internet connection to strictly sniff the air.
   5. Click Stop when finished. The packet capture (.pcap) file will automatically save to the /var/tmp/ directory. You can open this file directly in Wireshark. [2, 5, 6] 

## Option B: On Linux
Linux requires a compatible Wi-Fi card that supports monitor mode (common in distros like [Kali Linux](https://www.kali.org/) or using external USB adapters). [3, 6] 

   1. Open a terminal and find your wireless interface name (usually wlan0 or wlan1):
   
   iwconfig
   
   2. Put the interface down, switch to monitor mode, and bring it back up:
   
   sudo ip link set wlan0 down
   sudo iw wlan0 set monitor control
   sudo ip link set wlan0 up
   
   3. Lock the interface to your target Wi-Fi channel (e.g., channel 6):
   
   sudo iw dev wlan0 set channel 6
   
   
## Option C: On Windows
Windows does not natively support Wi-Fi monitor mode easily with standard drivers. To do wireless sniffing on Windows, you must either:

* Purchase a specialized USB Wi-Fi adapter that supports raw 802.11 frame capturing via Npcap (installed automatically with Wireshark).
* Run Linux inside a Virtual Machine with a USB Wi-Fi adapter passed directly through to the VM.

------------------------------
## Step 3: Capture and Decrypt the Packets
If you open Wireshark on Linux (or open the .pcap file generated by a Mac), you will see raw 802.11 wireless frames. However, because modern Wi-Fi is encrypted (WPA2/WPA3), the content of the data packets will look like gibberish. [1, 2, 7] 
To read the actual data traffic (like HTTP or DHCP requests), you must decrypt it: [2] 

   1. Capture the Handshake: Start your packet capture, then disconnect and reconnect the target device (like your smartphone) to the Wi-Fi network. Wireshark must witness the initial EAPOL 4-way handshake interaction to decrypt subsequent data. [2, 6, 7] 
   2. Add the Password in Wireshark:
   * Go to Edit > Preferences > Protocols > IEEE 802.11.
      * Check the box for Enable decryption.
      * Click Edit next to Decryption keys and select wpa-pwd as the key type.
      * Type in your Wi-Fi password and network name (SSID) formatted as: password:SSID. [2] 
   3. Click OK. Wireshark will now decrypt the over-the-air packets, exposing the fundamental IP and data stream. [2, 8] 

------------------------------
## Step 4: Isolate Traffic with Filters
Wireless captures collect massive amounts of background noise. Use Wireshark’s search bar to narrow your view:

* Filter by Device: Type wlan.addr == MAC_ADDRESS to isolate data coming to or from a specific device.
* Filter for the Handshake: Type eapol to check if you successfully captured the connection handshake needed for decryption. [2, 9]
